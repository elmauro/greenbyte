Add product-specific docs here as the project grows (vision, MVP plan, commercial notes).

## When to read

- Before scoping features or prioritizing work → `future-work/`
- When business context affects implementation, docs, or external messaging
- Before closing a feature → governance + registry sync

## Relationship to other context

- `docs/` — shipped product and operations documentation
- `cursor/projects/*/project-context.md` — stack-specific technical context
- `cursor/analysis/features/<slug>/` — temporary per-story artifacts
